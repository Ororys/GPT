# Reprise indépendante Health Convergence v3.0 → v3.1

15 novembre 2026. V1 strictement descriptive ; aucune donnée réelle ni déploiement public. Aucun score de risque, diagnostic ou module clinique ajouté.

1. **Fonctionnel à l'arrivée.** Les 77 tests annoncés sont reproduits : 45 unitaires, 26 PostgreSQL/HTTP, 6 Chromium. Le produit actuel utilise réellement PostgreSQL ; 378 observations fictives, registre, lecture, import, rapport, exports, profils de démonstration et journal fonctionnent dans le périmètre testé. Cela ne démontrait pas la sûreté des cas limites ni l'aptitude à la production.

2. **Défauts établis.** Perte des microsecondes et faux doublons ; course entre révocation et import ; versions d'une même mesure comptées plusieurs fois ; créations concurrentes de rapports en erreur d'unicité ; valeurs absentes provoquant une erreur SQL ; script local destructif ; reçu de migration séparé du DDL ; synthèse silencieusement tronquée. Les fonctions SQL acceptent aussi un sujet choisi par le rôle API et l'audit est annulable par ROLLBACK. Classement et preuves : AUDIT_TECHNIQUE.md.

3. **Corrections.** Migration additive 006, verrou de connexion pour l'import, verrou de rapport, précision conservée, validation explicite, refus des révisions non prises en charge, transaction DDL/reçu, démarrage non destructif avec secret local aléatoire privé, erreur de capacité UI, limites des calculs visibles dans le rapport. Ajout CI et tests de non-régression. Les connecteurs existants sont conservés ; aucun accès fournisseur inventé. L'héritage hors ligne reste séparé du produit. Dossier maître v3.1 ajouté sans modifier v3.0.

4. **Tests exécutés.** Sur le code ancien, cinq nouveaux tests démontrent les défauts par échec. Sur le code corrigé depuis un clone Git neuf et npm ci : **86 réussis**, aucun échec/ignoré (45 unitaires, 34 PostgreSQL/HTTP, 6 E2E réels, 1 test UI avec interception ciblée). Démarrage local et relance migrations/seed vérifiés, santé HTTP 200. Audit npm : zéro vulnérabilité connue. Docker et CI distante non exécutés. Détails, environnement et logs dans TEST_REPORT.md et docs/test-evidence/.

5. **Composants simulés.** Identité HS256 et sélecteur de profils ; CSV montre/laboratoire/centre sur données synthétiques. HealthKit, Health Connect et HL7/FHIR : contrats préparés, non configurés, refus 501. Aucun laboratoire, Garmin, appareil professionnel ou hébergeur de santé connecté.

6. **Risques résiduels.** Usurpation par rôle API compromis ; journal non indépendant de l'appelant/administrateur ; identité et consentement juridique absents ; jours UTC, moyenne par échantillon ; révisions refusées plutôt que traitées, doublons inter-fournisseurs non gérés, pas de conversion d'unités validée. Fractions perdues et doublons historiques nécessitent examen de la source. Pas de sauvegarde/restauration, charge, pentest exhaustif ou exploitation validée. PostgreSQL local utilisé pour l'audit n'est pas une recommandation de version de production.

7. **Décisions avant usage réel.** Fournisseur d'identité, enrôlement/MFA/révocation et preuve d'identité en base ; journal externe ; périmètre HDS et hébergement ; base légale/consentement/AIPD/rétention/rectification ; qualification réglementaire et relecture médicale de la V1 ; matrice soignants ; conventions fournisseurs ; unités, terminologies, fuseaux et agrégations validés ; sécurité indépendante et procédures d'exploitation testées. Voir BLOCKERS.md et BACKLOG_PRIORISE.md. **Le dépôt reste interdit aux données de patients réels ; aucune conformité HDS, RGPD ou MDR revendiquée.**
